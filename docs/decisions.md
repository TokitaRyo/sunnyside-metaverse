# 設計判断ログ

SPEC.md の指示に従い、判断と根拠を1行ずつ残す。実測値は末尾の「計測結果」。

## ライブラリ・API

- **Schema は Schema Builder（`schema()` / `t.*`）に統一。** `@colyseus/schema@5.0.33` の README が「デコレータから移行中（legacy decorators / `useDefineForClassFields:false` が esbuild・Vite と相性が悪い）」と明記しているため。
- **API は固定バージョンの実物（README・`.d.ts`）で確認した。** docs.colyseus.io のチュートリアルは概要ページのみ取得でき個別ページは 404 だったので、`colyseus@0.18.6` / `@colyseus/sdk@0.18.2` の型定義を一次情報とした。0.18 の要点:
  - サーバーは `defineRoom()`＋`@colyseus/tools` の `config()/listen()`（`defineServer` 系）。
  - 想定外の切断は `onDrop` → `allowReconnection(client, sec)`、確定した退室は `onLeave`。SDK は自動再接続が既定ON（`room.onDrop/onReconnect/onLeave`）。
  - クライアントの状態監視は `Callbacks.get(room).onAdd/onChange/onRemove`。
- **`uWebSockets.js` は tarball URL に `overrides`。** `@colyseus/tools` が git 依存で引くが、この開発機に git が無く `npm install` が失敗した。同一タグ（v20.52.0）の tarball を指定して回避。実行時の既定トランスポートは `ws`（`@colyseus/ws-transport`）で uWebSockets は使っていない。
- **`@metaverse/shared` は `paths`（tsconfig）＋ `exports`（package.json）の両方で解決。** `.ts` を直接公開する内部パッケージを tsc が node_modules 経由で解決しないため。実行時は tsx / Vite が `exports` で解決する。
- **プロジェクトは通常のフォルダに置くこと。** Claude デスクトップアプリの作業用フォルダ（`AppData\Roaming` の仮想化領域）配下だと、Vite が実パスの食い違いで TS を変換せず素のまま配信して起動できなかった。

## 同期

- **クライアント主導移動＋サーバー検証（Gather/ZEP 系）。** 操作の体感を優先。チートの実害が小さいため（SPEC 4.1）。
- **速度検証はトークンバケット。** 単純な「前回との距離 ≤ MAX_SPEED×dt×1.5」だと、回線の詰まり後にメッセージが連続到着した時に正当な移動を誤棄却する。許容移動量を時間で溜め（上限 0.5 秒分）、受理時に消費する。棄却時は `[reject]` をログし、本人にだけ `correct{x,y}` を返して座標を再同期する。
- **クライアント送信は 15Hz・値が変化した時だけ。** 静止中は送らない。patchRate は 50ms。`simulationInterval` は使わない。
- **1回再生のエモートは `emote` メッセージで再生、state.action は補助。** 同じエモートを連続で押すと state が変化せず patch が出ないため。持続型（座る）だけ state で伝え、遅れて入った人にも見える。
- **移動と `emote` の競合:** 歩き出したらエモートは即キャンセル（本人・相手側とも）。相手側は再生中エモートが終わるまで `idle` への戻りを待つが、`walk/run` は即反映。
- **タブを閉じたら `pagehide` で consented leave。** しないと `allowReconnection` 待ちの15秒間ゴーストが残る。
- **単一ルーム運用。** 起動時に `matchMaker.createRoom("main")` を1回だけ実行し（`autoDispose=false`）、クライアントは `join` のみ（`joinOrCreate` しない）。`joinOrCreate` だと満員時に2部屋目が自動生成され、51人目が無人の別部屋に入ってしまうことを実測で確認したため。満員時は「満員です」を表示。
- **モブはサーバー同期しない。** `map.json` の `mobs[]` を各クライアントがローカル描画（idle/waiting ループのみ）。全員が同じデータを読むので一致する（SPEC 4.5）。歩かせたくなった時だけサーバー管理へ。
- **チャットは 140 字・毎秒2通までをサーバーで強制。** 制御文字は除去。表示は `textContent` のみ（HTMLは解釈されない。`<b>` を送って確認済み）。

## 補間

- `t = 1 - 0.001^(dt)`（`REMOTE_SMOOTHING=0.001`）。60fps で1フレームあたり約11%詰める。15Hz送信・20Hz patch に対し、bot 30 体での実測（下記）でカクつきなし。96px 以上離れたら瞬間移動（入室直後・復帰時）。
- 自分のキャラはサーバー座標で上書きしない。`correct` を受けた時だけ例外的にスナップ。

## 描画

- **タイルは整数ズーム（2〜3倍）のみ。** 非整数だとタイル間に筋が出るため。`floor(min(w/320, h/200))` を 2〜3 に丸める。
- **props の基準点:** `x,y` はタイル左上の点に画像の「下端中央」を合わせる（`demo_map_render.png` と一致することを確認）。モブは足元原点 `(0.5, 0.625)`。
- **名前ラベル・吹き出し・チャット・エモートバーは Phaser の Text ではなく DOM。** ズーム×ピクセルアート設定下の Text は滲む／ギザつくため、日本語も含めてくっきり出せる DOM を、カメラの `POST_RENDER` で座標同期（1フレーム遅れなし）。吹き出し枠は `9slice_box_white`（`w_box_9slice_*`）を CSS グリッドで 3×3 に並べて実装。
- **入力は Phaser のキーボードを使わず window で直接取得。** Phaser の Key capture が入力欄への文字入力を `preventDefault` してしまう典型バグを避けるため。入力欄フォーカス中は移動キーを無効化。
- **必要な素材だけ読み込む。** 人間はプレイヤーが使うアクション（idle/walk/run＋エモート6種）×全レイヤー、モブとpropsは `map.json` が参照するものだけ。全 20 アクション×8レイヤーを読むより起動が軽い。フレーム数・パスは常に `sprites.json` から。

## マップ制作（村マップ `sunnyside_village`）

- **`map.json` は `scripts/gen-map.mjs` が生成する。** 手で 2400 セルを書き換えないため。固定シード乱数なので何度実行しても同じ結果。`node scripts/gen-map.mjs` → `client/src/config/map.json`。キット同梱のデモは `reference/map_demo_original.json` に残してある。
- **itch.io の紹介画像（`reference/itch/`、git 管理外）からのタイル ID 逆算は断念した。** スクリーンショットを 16px マスで素材と照合したが、完全一致は 2〜3 割に留まった（影・複数レイヤー・スプライト混在のため）。代わりに `tile_picker.jpg` を拡大して（`scripts/crop-tiles.ps1`）部品を目視で特定し、描画して確認する方法（`scripts/render-map.mjs`）に切り替えた。
- **autotile グループ(16枚)の並びは実測で判明（`scripts/lib/tilekit.mjs` に記録）。**
  - 添字 0=べた塗り / 12=上端に縁 / 3=下端 / 10=左端 / 5=右端 / 1,2,4,8=斜めの角（左上・右上・左下・右下）。**縁の左右は直感と逆**（添字5が右端）。
  - **道(Path 01/02)は「土の上に草の縁取りを重ねる」**。縁取りは領域の内側セルに置き、凸角は斜めタイルで丸める。
  - **川(River)は逆に「水の上に草を重ねる」**。縁取りは水に接する陸側セルに置く。水セルの角は草の三角で丸める。
  - 凹角（十字路の内側など）用の小片(添字 6,7,9,11,13,14)は未使用。接合部にごく小さな欠けが出るが、実プレイでは目立たない。
  - 幅2の道は両端の斜めが合わさって矢印状になるので、道は幅3にし、マップ端まで伸ばして端を見せない（`clampEdges`）。
- **家はタイルセットの部品からは組めなかった。** 家の部品(屋根・壁・戸・破風)は 16px グリッドに揃っていない切り出しで、組み合わせ規則が画像からは読み取れなかった。そのため手組みの村マップ(`gen-map.mjs`)では家を置かず、柵で囲った畑・牧場・墓地、池、石垣、像、井戸、焚き火で「村らしさ」を出した。**家は次節の公式ルーム取り込みで解決した**（家は `building` タイル層に配置済みだった）。
- **風車(`windmill*`)は羽根だけのスプライトで本体が無い**（本体は `building` 層のタイル）。手組みマップでは置かない。公式ルームでは塔のタイルに羽根が重なっている。

## 公式ルーム(Room1)の取り込み（標準マップ `sunnyside_world_example`）

元パック `Sunnyside_World_ASSET_PACK_V2.1/Sunnyside_World_Gamemaker/rooms/Room1/Room1.yy` に、公式の全体マップ（`Sunnyside_World_ExampleScene.png` の元）が入っていた。これを `scripts/import-gm-room.mjs` で変換している。推測は不要で、家・崖・川・橋・はしご・鉱山まで元の配置どおりになる。

- **入力の構造（86×48タイル）:** タイル層13枚(`sea land paths shadows decoration_01/02/03 building walls forest(32px) clouds_01/02 cloud_shadow`)、配置物(Assets_1/2)570個、スプライト112種。タイルは RLE 圧縮（負の数=繰り返し・正の数=リテラル、`-2147483648`=空き）。
- **タイル値のフラグ:** 下位19bit=タイル番号、bit28=ミラー、bit29=フリップ、bit30=回転。**「ミラー/フリップ → 90°時計回り回転」が正解**（4通りを描画して比較し、他の解釈では水面に余計なタイル片が出る／広範囲でずれることを確認。`scripts/gm-tiles-test.mjs`）。**変換つきタイルは、変換済みの見た目を素材PNGの末尾行に焼き込んだ拡張タイルセット**(`sunnyside_16_ext.png`、411枚追加)にし、実行時はフラグを一切扱わない。
- **map.json の拡張（任意項目）:** `tilesets`（使うタイルセット）/ `tileLayers`（`mode`= floor・ysort・top の任意枚数）/ `sprites`（スプライトシート定義と原点）/ `objects`（ピクセル座標の配置物）。従来の `ground/deco/overhead/collision`・`props`・`mobs` はそのまま使える。`tileLayers` があるときだけ新しい描画経路を使う。
- **前後関係:** `floor` はキャラより下。**`ysort` は1行ずつ別の層にして depth=その行の下端Y**（建物の裏を歩くと隠れ、手前では重なる）。配置物は足元Y（原点から見た下端、キャラ96×64は原点+8）で並べる。`top`（雲）は最前面だが、プレイヤーが隠れきらないよう不透明度0.6にした。
- **配置物:** 位置は原点基準のピクセル、拡大率は負でミラー、回転は GameMaker が反時計回りなので符号を反転。`headPosition` は負になりうる（周期で回る）ため 0..frames-1 に正規化する（未対応だと Phaser が `startFrame` 範囲外で例外を投げる）。アニメ速度はスプライト定義の fps。
- **衝突判定は元データに無いので導出した（86×48）:**
  - 歩ける = `land` 層のタイルが草・砂・土（色で判定。**茶色が7割超のタイルだけ崖の面**、水は青系が4割超）。台地の縁の斜めタイルは歩ける側。
  - `paths` 層の**ほぼ不透明なタイル(30%以上)は下が水や崖でも歩ける**（橋・桟橋・坂道）。縁取りの細い帯は除く。はしご(`decoration_01` の 746/810/874)も歩ける。
  - `building`・`walls` のタイルと、森タイル(32px)の**下半分(幹)**は通れない。木・樽・箱・井戸などの配置物は足元の小さな判定(`hit`)を持つ。
  - **柵・家具などの装飾タイル(`decoration_02/03`)は塞がない。** 塞ぐと台地・畑・牧場が分断され本島の連結領域が半減する（629→1186マス）。元のゲームでも見た目だけ。
  - 本島は歩行可能 1186 マスで連結。**左上の畑の台地・左下の鉱山・右上の砂浜の一部などは飛び地**で、スポーンは本島の中央付近（連結成分の最大の中）。
- **スポーンの落とし穴:** サーバーが「中心点」だけで衝突判定してスポーンさせていたため、足元12×8が壁マスに掛かり**全方向に動けなくなる**不具合があった。サーバーで足元矩形(`isFootBlocked`)を判定し、ジッターも1.5タイルに縮めた。あわせてクライアントも「すでに埋まっている時は判定を外して抜け出せる」ようにした。
- **性能:** ysort 行の層が約137、スプライト570。`game.step()` 1回(描画込み `gl.finish` まで)は中央値 2.7ms・p95 6.3ms で 60fps の予算(16.7ms)に収まる。bot 30体接続でも同様。
- **ライセンス:** 取り込んだ配置データ・スプライトは元パックの素材由来で、再配布は禁止。`client/public/assets/{gm,tilesets/*_ext.png}` と `client/src/config/map.json` は素材を含むので、リポジトリを公開する場合は `.gitignore` で除外すること。
- **柵は「端・中間・角」の実測タイルで組む（`gen-map.mjs` の `F`）。** 柵タイルは衝突あり。
- **props の座標は小数タイルを許可**（作物を畑の各マスの中央に置くため）。`hitbox:{w,h}`(px) で当たり判定の大きさを指定できる（省略時 12×8）。
- **プレイヤーが使わない人間アクション（釣り・水泳・運搬）は、そのモブの髪型のレイヤーだけ読む。** 全髪型ぶん読むより約17ファイル減る。

## マップエディタ（開発時のみ）

- **Tiled ではなく、ゲーム内のエディタにした。** 標準マップは「反転・回転を焼き込んだ拡張タイルセット」「ピクセル座標の配置物」「導出した衝突」を持つ独自形式で、Tiled との往復変換が重いうえ、衝突や当たり判定は Tiled 上では見た目と切り離される。ゲームと同じ描画のまま、衝突（赤）と判定枠（黄）を重ねて直接直せる方が調整が速い。
- **構成:** `EditorScene` は `WorldScene` を継承（描画・マップ構築は共通、接続と自動ズームだけ無効化）。UI は DOM パネル(`EditorPanel`)。`main.ts` で `import.meta.env.DEV` のときだけ動的 import し、**本番バンドルには含まれない**（ビルド後の文字列検索で 0 件を確認）。
- **編集はメモリ上の `map` オブジェクトを直接書き換え、履歴(Cmd)で元に戻す/やり直しを管理。** ドラッグ操作は1ストロークを1つの履歴にまとめ、素早いドラッグでマスが飛ばないよう前回位置から補間して塗る。「未保存」判定は次節のプレイ⇄編集の行き来があるため、履歴の位置ではなく専用フラグ(`hasUnsaved`)で持つ。
- **タイル編集の見た目反映:** `floor`/`top` 層は `putTileAt`、`ysort` 層は行ごとの層に反映（空だった行は層を新規作成）。透明タイルのスタンプ貼り付けは既定でスキップ。
- **物の選択は「クリック位置に絵がある一番手前」**（テクスチャのアルファで判定。96×64のゴブリンの透明な余白で隣の物を奪わない）。新しい物の足元Y・当たり判定の初期値は取り込みスクリプトと同じ規則（`objectDefaults.ts`）。
- **保存API（`vite.config.ts` のプラグイン、`POST /__editor/save`）:** `client/src/config/map.json` を書き換え、上書き前のファイルを `reference/map-backups/` に退避。dev サーバーは `host:true` で LAN に公開されるので、**書き込みは localhost からのリクエストに限定**。サーバー側(`tsx watch --include ../client/src/config/map.json`)は `map.json` の変更で再起動し、衝突判定が反映される。
- **確認したこと:** 選択・ドラッグ移動・元に戻す、衝突ペイント（補間つき）、パレット選択→タイル描画→元に戻す/やり直し、物の追加・削除・元に戻す、保存（ファイル更新＋退避ファイルが元と同一）。テストで書き換えた `map.json` は退避ファイルから復元し、ハッシュが一致することまで確認した。

### モブのカタログと影の連動（エディタ）

- **カテゴリ:** ゴブリン(96×64のキャラ)・スケルトン・人間・動物/鳥・その他。日本語名と、体のまわり32×32を切り出したサムネイルで一覧表示（96×64の余白だらけの絵だと何か分からないため）。
- **カタログ項目(`sprites[*].catalog=true`):** マップで使っていない種類（ゴブリンの全20動作、スケルトン6種、動物6種、人間 髪型6×動作5）も、エディタから置けるよう `map.json` に定義だけ登録。**ゲームは配置物で使われているものしか読み込まない**（エディタ `?edit=1` のときだけ全部読む）ので、通常の読み込み量は変わらない（186ファイルのまま）。人間は素材の base+髪+tools の3枚を合成した1枚のシートにした（`scripts/lib/mobcatalog.mjs`）。
- **既存の `map.json` を作り直さない:** 取り込みスクリプトを再実行するとエディタでの編集が消えるため、`add-mob-catalog.mjs` は `sprites` に項目を足すだけにした（実行前に退避）。
- **影は「別の物」として実データで測って決めた:** ゴブリンの影は足元(o.x, o.by)の (0,-1)、スケルトンは (0,-8)、人間はゴブリンと同じ。**動物・鳥に影の物は付いていない**（牛・羊・豚・鶏・アヒル・鳥は絵に影が含まれる。測定で影の対応が見つかったのは偶然近くにあったゴブリンの影だけ）。
- **モブと影の対応づけ:** 影は別オブジェクトなので、種類ごとの標準位置から 12px 以内の影を、近い順に1対1で割り当てる（貪欲法）。既存データでゴブリン 64 体中 47 体に影があり、残りは影なしのまま。ドラッグ開始時に対応を確定するので、動かしている最中に相手が変わらない。
- **移動・複製・削除は影とセットで1回の「元に戻す」**（設定で切り替え可。影だけの追加・削除もできる）。
- **元に戻すの不具合を先に潰した:** 以前は「削除→元に戻す」で物が別の実体として作り直され、それ以前の移動の履歴が壊れたスプライトを指した。物の**本体(ObjectEntry と o データ)は同じまま、絵(スプライト)だけ作り直す**方式に変更（`attach/detach`）。確認: 置く→移動→削除→元に戻す→さらに元に戻す で座標が正しく戻る。

## プレイ画面とエディタの切り替え

画面右上の「🛠 マップを編集」／「▶ プレイ画面に戻る」ボタン（`main.ts` の `setupDevToggle`、開発時のみ生成）で、ページを再読み込みせずに何度でも行き来できるようにした。実装前に Phaser のシーン停止の仕様を調べ、想定より安全だと分かった一方、DOM側の後片付けは自前でやる必要があった。

- **Phaser 側は自動で片付く。** `Systems.shutdown()` のコメントに反して「プラグインは破棄されない」が、`DisplayList` は自分で `SceneEvents.SHUTDOWN` を購読していて、シーン停止のたびに子(スプライト・タイルレイヤー・Graphics・Container)を**全部 `destroy(true)` する**（`node_modules/phaser/src/gameobjects/DisplayList.js`）。`InputPlugin` も同様に `shutdown()` で `removeAllListeners()` する。つまり `this.add.*` で作ったものや `this.input.on(...)` は、`game.scene.stop()` のたびに自動で消え、次の `create()` で作り直しても重複しない。**これは実験・ソースコード確認済みで、シーンをまたいだ自前の破棄コードは不要**（安易に `this.children.removeAll(true)` 等を足す必要はない）。
- **Phaser が関与しない部分は自前で片付ける必要がある。** 具体的には3か所:
  1. `window.addEventListener(...)`（`EditorScene` のキー入力、`WorldScene` の `pagehide`、`EditorPanel` の `beforeunload`）— Phaser のシーンライフサイクルと無関係なので、素朴に毎回張ると積み重なる。インスタンスフィールドの真偽値で「ページで1回だけ」に統一した（同じシーンインスタンスがページの生存期間ずっと使い回される前提。`EditorPanel` だけは毎回作り直すオブジェクトなので、リスナー参照を保持して `destroy()` で `removeEventListener`）。
  2. **静的な HTML 要素（`index.html` にあるチャット欄・パッドのボタンなど）へのリスナー。** `Hud` は入室のたびに新しいインスタンスを作るが、`bindChat`/`bindPad` は同じ要素に `addEventListener` するので、毎回張ると**チャット送信やパッド操作が多重発火する**（例: 2回目の入室後にEnterを押すとメッセージが2通届く）。`Hud.current`（最新インスタンスへの参照）を持つ静的フィールドを導入し、静的リスナーは**ページで1回だけ**張って常に `Hud.current` へ委譲する方式にした。エモートバーは動的に作るボタンなので、こちらは単純に「毎回 `replaceChildren()` してから作り直す」で重複を防いだ。
  3. **`#ed`（エディタパネル）・`#labels`（名前ラベルの入れ物）などの DOM の表示状態。** `EditorScene.create()` は毎回 `new EditorPanel()` するので、古いパネルを `destroy()` しないと2枚重なる。`EditorPanel` コンストラクタは `#labels` を非表示にするが、対になる「戻す」処理がどこにも無かったので `destroy()` に追加（さもないと編集を1回でもすると名前ラベルが二度と出なくなる）。
- **スプライト参照はセッションをまたいで持ち越さない。** `EditorScene.create()` の冒頭で `history`/`hi`/`selected`/`drag`/`ghost`/`ghostShadow` をリセットする。理由: プレイ画面との往復で配置物のスプライトは（上記の自動破棄で）作り直されるため、古いセッションの履歴やゴーストが指すスプライト参照は無効になる。データ(`map.objects` 等)自体は共有オブジェクトなので編集内容は消えず、見た目にも反映され続ける——**「未保存」フラグは別管理にしたことで、セッションをまたいでも正しく残る**（確認済み: 牛を1体置いてプレイへ→エディタへ戻すと、配置は残り「未保存の変更あり」も残るが、元に戻す履歴は空にリセットされている）。
- **入室フォームの使い回しで見つけた不具合:** `JoinScreen` は「入室する」を押すと `busy=true` にするが、それを戻すのは成功時の `hide()` ではなく `showError()` の中だけだった。以前は入室画面を1回しか出さなかったので問題にならなかったが、エディタから**プレイへ戻って再表示すると「接続中…」のまま固まって**しまう。`JoinScreen.reset()` を追加し、プレイへ切り替えるたびに呼ぶ。
- **未保存の変更はプレイ中にも見える。** `map` はブラウザ内で1つだけの共有オブジェクトなので、保存前でもプレイ画面は編集内容をそのまま描画する（試しにプレイしながら配置を確認できる）。ただし**サーバー側の衝突判定は保存済みの `map.json` を読んでいる**ため、衝突を変えた直後は見た目とサーバー判定がずれることがある（README に明記）。
- **接続中の競合:** 入室处理が完了する前にエディタへ切り替えられる場合に備え、`WorldScene.connect()` は `await this.net.join(...)` の直後に `this.scene.isActive()` を確認し、非アクティブなら静かに退室するだけにして `Hud` を作らない。
- **URL との同期:** 切り替えのたびに `history.replaceState` で `?edit=1` を付け外しする。保存後は Vite が自動でページを再読み込みするので、これが無いと保存のたびにプレイ画面に戻ってしまっていた。
- **確認したこと:** Play→Edit→Play→Edit を繰り返しても、チャット欄の多重送信なし・エモートボタンが6個のまま重複しない・`#ed` パネルが1枚だけ・名前ラベルの入れ物が正しく表示に戻る・エディタに置いた物と「未保存」表示がプレイ画面を挟んでも残る・選択とドラッグ移動が古い参照でエラーにならない、をブラウザで実測して確認した。本番ビルドにはトグル関連の文字列が含まれないことも確認済み。

## デプロイと CI（GitHub Actions → Fly.io）

- **素材の非公開分離。** `client/public/assets` と `map.json` は再配布禁止ライセンスのため、公開リポジトリ(`sunnyside-metaverse`)には含めない。CI（GitHub の共有ランナー、ローカルPCとは別環境）はこれらのファイルを一切持っていないので、**ビルド直前に非公開リポジトリ `sunnyside-metaverse-assets` から取得**する構成にした。手元からの `flyctl deploy` は今までどおりローカルのファイルをそのままアップロードするので影響なし。
- **CI の認証はリポジトリ限定の read-only Deploy Key。** 個人の PAT（全リポジトリに読み書き可能な `gh auth token` など）を流用すると権限が広すぎるため、`ssh-keygen` で専用鍵を作り、公開鍵を `sunnyside-metaverse-assets` の Deploy Key（読み取り専用）として登録、秘密鍵を `sunnyside-metaverse` 側の Secrets(`ASSETS_DEPLOY_KEY`)に保存した。この鍵は素材リポジトリ以外には一切アクセスできない。
- **Fly.io 側もアプリ限定トークン。** `flyctl tokens create deploy -a sunnyside-metaverse` で、このアプリの操作にしか使えないトークンを発行し `FLY_API_TOKEN` として保存（組織全体を操作できる個人トークンは使わない）。
- **ワークフロー（`.github/workflows/deploy.yml`）:** `main` への push で起動。`actions/checkout` → SSH で素材リポジトリを `git clone --depth 1`（鍵は実行後に削除）→ `client/public/assets` と `map.json` を配置 → `superfly/flyctl-actions/setup-flyctl` → `flyctl deploy --remote-only`。
- **やり直した失敗:** `git clone`/`git push` を素のコマンドで叩いたところ、`gh` ではログイン済みでも Git 自体には資格情報が渡っておらず `terminal prompts disabled` で失敗。**`Set-Location` が失敗した後もスクリプトの以降の行がメインリポジトリのディレクトリで実行され続け、素材リポジトリ用に書いた README.md を誤ってメインリポジトリの README.md に上書き・コミットしてしまった**（push 前だったので `git reset --soft` + `git checkout <直前のコミット> -- README.md` で復旧、実害なし）。教訓: 複数ステップのシェルスクリプトでは `Set-Location` 直後に `(Get-Location).Path` を検証して一致しなければ `throw` するなど、失敗時に後続処理へ進ませない防御を必ず入れる。原因は `gh auth setup-git` を先に実行していなかったこと（`gh repo create --push` は内部で別経路を使うため、素の `git push` が失敗することに気づきにくい）。
- **`gh secret set` に `<` でファイルを渡すのは Windows PowerShell 非対応。** `--body-file` フラグも存在しない。`Get-Content -Raw -Path <file> | gh secret set NAME` のようにパイプで渡す。

## BGM

- **Phaser の audio は使わない。** `main.ts` の Game 設定で `audio: { noAudio: true }` にしているため、BGM は Phaser Sound Manager を経由せず素の `HTMLAudioElement`（`client/src/audio/Bgm.ts`）で完結させた。ページ内でシングルトン1個だけ持つので、マップエディタとの行き来（シーン切り替え）をまたいでも鳴り続ける。
- **再生開始は「入室する」クリックのハンドラ内。** ブラウザの自動再生制限（ユーザー操作なしの `play()` は拒否される）を通すため、`join.onSubmit` の中で同期的に `bgm.start()` を呼ぶ。
- **素材は非圧縮wav（合計400MB超）で受け取ったため、`ffmpeg`（winget `Gyan.FFmpeg`）で mp3 128kbps に変換して同梱（9曲で計約19MB）。** ロスレスのまま配布すると読み込みが重すぎる（文化祭当日のスマホ回線を想定）。フォーマットは iOS Safari を含む対応幅を優先して mp3 を選択（ogg/opus は Safari 非対応）。
- **BGM音源も画像素材と同じ非公開リポジトリ(`sunnyside-metaverse-assets`)扱い。** 出所（ユーザーがダウンロードした既成のBGM）のライセンスをこちらで確認できないため、既存の画像素材と同じ「公開リポジトリに含めない・CIがビルド直前に非公開リポジトリから取得する」構成に統一した。
- ミュート状態は `localStorage` に保存。音量は固定 35%（調整UIは無し、ON/OFFのみ）。

## チャットのNGワードフィルタ

- **`server/src/rooms/MainRoom.ts` に簡易フィルタを追加。** 展示中は共有画面にチャットが映るため、脅迫（死ね／殺す等）・強い侮辱・差別語のみを伏字にする最小限のリストを持つ（`NG_WORDS` 配列。追加は配列に足すだけ）。「ばか」等の軽い言葉は対象外（過剰検閲より実害の大きい語だけを止める方針）。完全なモデレーションではない前提。

## 学校マップ（`sunnyside_school`）

- **地形は村マップと同じ `tilekit.mjs` のオートタイル(Land/Path/River)で新規に塗り、校舎そのものは公式マップ(`sunnyside_world_example`)の実在する建物を2棟、タイルの矩形ごと「移植」した。** この素材(`sunnyside_16` 系)には壁・屋根の絵は無く(`Building 01/02` は室内の床テクスチャ)、ゼロから学校建築を描き起こすのは非現実的なため。移植元の矩形は `reference/crop_candidate*.png` で目視確認して実測した(校舎A: 元マップ x39,y24,7x7 の切妻屋根の建物／校舎B: x32,y19,5x6 の赤屋根の小屋)。矩形は建物ぴったりに絞る(隣接する川・崖・切り株ごと持ってきてしまうと継ぎ接ぎに見える)。
- **当たり判定(`layers.collision`)は tileLayers を使っていても独立した平面配列のまま。** `server/src/map.ts` と `WorldScene.blocked()` はどちらも `layers.collision` しか見ないため、公式マップのような「タイル色から歩行可否を推定する」処理は不要で、建物の外形に合わせて自分で `collision.set(x,y,1)` すればよい(下2行だけ玄関として空ける、という単純なルールにした)。`layers.ground/deco/overhead` は tileLayers があると描画に使われないため、寸法だけ合わせた全 `-1` で埋めて `validateMap` を通している。
- **陸上トラックは楕円ではなく「角丸長方形のリング」。** `paintRegion` の角丸め処理は隣接マスの有無で角タイルを選ぶため、楕円マスクだと境界の凹凸で棘のようなアーティファクトが出た。矩形の外側マスクから内側マスクを引いたリングにしたら綺麗な角丸になった。
- **`scripts/gen-school-map.mjs`** で生成 → `scripts/check-map.mts`(`validateMap` を Node から直接叩く簡易チェッカー、新規)で検証 → `client/src/config/map.json` に反映、の順。切り替え前に `reference/map-backups/` へ手動バックアップを残した。
- **本番(Fly.io)へはまだ反映していない。** ユーザーがモブ配置やタイルをエディタで直接調整したいと明言しているため、ローカルで確認・調整してから非公開の `sunnyside-metaverse-assets` リポジトリへ push する運用にする。

## 白紙キャンバス（ユーザーが0からエディタで作る）

- 学校マップの自動生成(`gen-school-map.mjs`)は「素材に建物の絵が無く農村風のままになる」という理由でユーザーが不採用と判断。**代わりにユーザー自身がエディタで0から作ることになった。**
- `scripts/gen-blank-canvas.mjs` で、公式マップと同じ `tilesets`(main/forest)・`sprites` カタログ・`tileLayers` の構成（レイヤー名・モードも同じ: sea/land/paths/shadows/decoration_01→building→walls→decoration_02/03→forest→clouds…）だけを引き継ぎ、中身(タイル・配置物・当たり判定)は全部空にした `map.json` を生成する。エディタのパレットは `map.tilesets`/`map.sprites` の「定義」を見るだけで、置いてある中身とは独立なので、空でもパレットには元の絵がそのまま出る（`?edit=1` で実機確認済み）。
- サイズは公式マップと同じ 86×48 を既定にした（`--w`/`--h` で変更可）。

## マップエディタの「パーツ」（プレハブ）機能

- ユーザーが0からエディタで作るにあたり、「家・木立など複数パーツに分かれた物を1クリックで置けるようにしてほしい」との要望。新しい `Tool = "prefab"` を追加した（キー `G`）。
- **データ形式(`client/src/editor/prefabTypes.ts`):** 1つのパーツは「複数レイヤーぶんのタイル」「当たり判定マス」「配置物」の3種類をまとめて持つ。レイヤーは**配列の並び順ではなく名前**（`sea`/`land`/`building`/`walls`…）で対応づけるので、将来レイヤー構成が変わっても壊れにくい。
- **建物3種(`prefabs.generated.ts`)は公式マップ(sunnyside_world_example)から実測・自動生成。** `scripts/gen-prefabs.mjs`（`gen-school-map.mjs` の「建物移植」を汎用化したもの）が、目視確認済みの矩形（青い大きい家/赤い小屋/紫の家）を、tileSize が一致するレイヤーだけ対象に、タイル・付属物(煙突の煙)・当たり判定(下2マス＝入口だけ歩ける)ごと抽出する。手で編集しないファイルなので冒頭に自動生成の注記あり。**forest(32px)のようにタイルサイズが違うレイヤーは対象から除外**（16pxマス単位のdx/dyと単位が合わず、別の場所のタイルを誤って拾うバグになるため。実害が出る前に気づいて直した）。
- **草木・門(`prefabs.ts`)は手作り。** 花壇・茂みは装飾タイル(`decoration_01`、常にキャラより下)、門は`walls`(ysortで前後判定)に置く。木立・岩は実在のオブジェクト("spr_deco_tree_01"/"rock")をそのまま複数個並べる（タイルは使わない）。
- **配置は複数タイル・複数レイヤー・当たり判定・配置物の変更を1回の「元に戻す」にまとめる。** 通常の物1個・タイル1ストロークの undo とは別に、`EditorScene.placePrefab()` で全変更を集めてから `push()` を1回だけ呼ぶ。
- **パレットのサムネイルは事前レンダリングした画像ではなく、実際に読み込み済みのタイルセット/スプライト画像から都度切り出して描く。** データと見た目が常に一致し、パーツを増やしても追加の画像生成が要らない。
- 置く位置はクリックした位置が**パーツの左上**（タイルツールのスタンプと同じ流儀）。置いた後の移動はできない（間違えたら元に戻す）。

## エディタ改善（消す／ワープ／プレイ範囲表示）

- **「消す」ツール。** パーツを置いた場所を丸ごと消したい、という要望。ドラッグしたマスの**全レイヤーのタイル・当たり判定・物（影も含めて）**を一括で消す。個別に1個だけ消したいときは従来通り「選択・移動」→Delete。
- **ワープタイル。** 「特定のタイルに触れるとブラックアウトして画面遷移」の要望。`map.warps: {x,y,toX,toY}[]`（マス座標、1マス=1件）を追加し、エディタに専用ツールを作った（左ドラッグ=設定、右ドラッグ=解除、パネルの数値入力で移動先を指定、紫のマス＋水色の移動先マス＋結ぶ線で常に見える）。
  - **サーバーが権威。** 移動速度の検証(`handleMove`)を通った**後**に、新しい座標がワープマスに乗っているか`this.map.warpAt()`で調べ、乗っていればサーバー側で座標を移動先へ書き換え、速度予算(`peer.budget`)を全回復させ、`correct`メッセージ（`warp:true`つき）で本人にだけ知らせる。クライアントが「ワープした」と自己申告する方式にしなかったのは、任意の座標へ飛べてしまうチートになるため。
  - **`correct`メッセージを流用。** 棄却時の「正しい座標を返す」チャンネルと同じ仕組みを使い、`warp`フラグの有無だけで「暗転してから瞬間移動」か「即座に補正」かをクライアントで分けた（`WorldScene.onCorrect`）。新しいメッセージ種別を増やさずに済んだ。
  - **動作確認はColyseusクライアントを直接叩くスクリプト(`scripts/warp-test.ts`、`cheat-test.ts`と同じ作法)で行った。** ブラウザの自動操作ではキー入力やバーチャルパッドのクリックがゲーム内キャラクターの移動として反映されないことがある（この環境固有の制約）ため、実際に歩いて確認する代わりにサーバーのメッセージフローを直接検証した。
- **プレイ画面の範囲表示。** 「編集中、実際に画面へ映る範囲が分からない」の要望。スマホ想定(390×700 CSS px)でのズーム・可視範囲を`applyZoom()`と同じ式で計算し、カーソル中心に緑の矩形を出すチェックボックスを追加。

## リタイル（`scripts/retile.mjs`）

- ユーザーが「タイル」ツールで単色のタイルを敷き詰めた地面（緑・茶）を、「自然な感じ」に描き直してほしいとの依頼。以後この種の作業を「リタイル」と呼ぶ。
- **色をタイルIDで決め打ちせず、タイルセット画像の平均色から緑/茶を自動分類する。** 次にユーザーが別の場所を塗っても、色さえ緑・茶系ならそのまま使い回せる（`classify()`）。
- 検出したマスをいったん空にしてから、`tilekit.mjs` の `paintRegion()`（村マップ生成で使ったのと同じオートタイル処理）で `land`(緑=Landグループ)・`paths`(茶=Path 01グループ)に塗り直し、境界の縁取りは `decoration_01` に重ねる。角の凹凸も自動でなめらかになる。
- 緑の範囲には `GRASS_DETAIL` の草むら模様を8%程度の密度でランダムに散らし、単調さをさらに減らす。
- 建物・柵・当たり判定・配置物・ワープには触れない（対象レイヤーは land/paths/decoration_01 のみ）。

## 範囲選択（矩形の一括削除・複製）

- 「ドラッグで選んだ範囲を一括削除／複製して好きな場所に置きたい」という要望。新しいツール「範囲選択」(`B`)と、その延長にある「スタンプ」を追加した。
- **削除は「消す」ツールと同じ土台。** 矩形内の全セルに対して `setTile(-1)`/`setCollision(0)` を回し、既存の `finishStroke()`（タイル・当たり判定をまとめて undo に積む仕組み）にそのまま乗せた。物の削除も既存の `deleteEntries()` を再利用。新しいコードはほぼ「1マスずつのループを矩形に対して回す」だけで済んだ。
- **複製は「パーツ」システムを流用。** 選択範囲の中身（タイル・当たり判定・物）を、パーツと全く同じ形(`Prefab`型)のデータに変換して `clipboard` に持たせ、「パーツを置く」処理(`stampPrefab`、旧`placePrefab`から抽出)をそのまま呼ぶだけにした。「パーツ」も「範囲選択からの複製」も中身は同じ関数が置いている。
- スタンプ中は Esc または専用ボタンで「範囲選択」に戻れる。置いた後もスタンプモードは続くので、同じ範囲を連続で何度でも置ける。

## 青空・雲・浮島（`scripts/gen-sky.mjs`）

- 「マップ一面を青空に、雲と浮島も」の依頼。公式マップは「雲海に浮かぶ島」なので、**空＝`sea`レイヤーの海タイル**。公式は `(18+y%4)行・11+x%4列` の4×4を全面に繰り返しているので、同じ式で空きマスを埋める。
- **浮島は公式の小さな島を「型」に分解して、幅・高さを変えて量産。** 行は 縁(T)・草の面(I)×k・草の下端(B)・崖×3(C1〜C3)、列は 左端2列・中央m列(繰り返し)・右端2列。崖は拡張タイルセット(4096番台)の反転・回転済みタイルを使う。島ごとに木(`spr_deco_tree_01/02`)を数本立てる。
- **雲は `paintRegion` が使えなかった。** Land/Path は「縁タイルを地面の上に重ねる」前提だが、雲の縁・角タイルは1枚で雲の形を持つ。公式の雲の並びから実測して、`tiles`配列の index を 縁 N=3 S=12 W=5 E=10／外側の角 TL=7 TR=11 SW=13 SE=14／内側の角 TL=1 TR=2 BL=4 BR=8 と割り当てた。島と重なる雲は欠けた形になるので置かない。
- **当たり判定: 空は通れない。** 地面(`land`/`paths`)が無いマスを塞ぐ。島の草の面だけ歩ける、崖は塞ぐ。**スポーン(`map.spawn`)が空の上だと動けなくなるので、スポーンを中心にした島を最初に置く。**
- 空きマスに足すだけで、既存の地面・建物・配置物・ワープは消さない。

## タイルで貼った物を「1つの物」として扱う（グループ）

- 「パーツ・スタンプ・島など、タイルで貼ったものも、1つの物として当たり判定・選択・移動したい」という要望。タイルは本来セルの値でしかなく「どこからどこまでが1つ」という情報が無いので、**貼ったときに `map.groups`(`GroupDef`)として記録する**ことにした。`{x,y,w,h, tiles[], collision[], warps[]}` で、位置はすべて左上からの相対。ゲーム本体は読まず、エディタだけが使う。
- **各セルに「置く前の値(`prev`)」を持たせる。** 移動・削除では、いまの値がグループのものであれば `prev` に戻し、新しい位置に置き直すときに `prev` を取り直す。これで、動かしたあとに下の地面が壊れない。当たり判定は `v`(グループが入れる値)と `prev` の両方を持つ（島は「草=0(歩ける)、崖=1」を空=1の上に置くので、塞ぐだけでなく開ける向きもある）。
- **配置物(`ObjectDef.group`)とワープ(`GroupDef.warps`)も一緒に動く。** 家の煙突や島の足場が置き去りにならない。ただし他の島の足場から**この島へ向かう**ワープ先は絶対座標なので、島を動かしたらつなぎ直しが要る。
- 選択は「選択・移動」ツールで、配置物に当たらなければそのマスを含むグループを選ぶ。ドラッグ・矢印キー・インスペクタのx/y入力で動かし、1回の操作が1つの「元に戻す」になる。Delete でまとめて削除。インスペクタで当たり判定（なし／全面／建物＝下2行だけ通れる）も作り直せる。

- **不具合の教訓: 同じ情報を2か所に持つと、片方だけの更新で食い違う。** ワープは `map.warps`(実体)と `GroupDef.warps`(島に付いて動くための記録)の両方にあり、ワープツールで消しても後者が残ったため、島を動かすと消したワープが復活した。ユーザー操作でのワープの設定・削除は必ず `setWarpCell()` を通し、グループの記録も同時に更新する（グループ移動の内部処理は従来どおり `applyWarp()` を直接使う）。新しく設定したワープがグループの範囲内なら、そのグループのものとして記録し、島と一緒に動く。

- **不具合の教訓: window に張ったリスナーは、シーンが止まっても生きている。** エディタのキー入力(`onKey`)は `window` に1回だけ張る作りなので、プレイ画面に切り替えたあとも動き続け、**エディタで選んだままの島が、プレイ中に矢印キーを押すたびに動いた**（Delete なら消えた）。止まったシーンのタイルレイヤーは破棄済みで `applyTile` が途中で例外を出し、島の地面タイルが欠けた（再現: 島を選択→プレイ→↓キー3回で 138→135 個）。対策は `onKey` の先頭で `this.scene.isActive()` を見ることと、エディタの SHUTDOWN で選択・ドラッグ・範囲選択の状態を捨てること。欠けた島は `scripts/repair-groups.mjs`（グループの記録から空のマスだけ復元）で直せる。

## 島どうしのワープ（`gen-sky.mjs --grid`）

- 隣り合う島の4辺(上下左右)に、黄色い足場(Path 03のタイル)を3マス幅で置き、隣の島の反対側の足場の**2マス内側**に飛ばす。着地点は足場ではないので、着地した瞬間に戻されることがない。足場とワープは島のグループに含めてあるので、島を動かしても足場は付いてくる。
- 動作確認は `scripts/warp-test.ts`（`map.json` の実際のワープを1つ選び、歩いて乗せ、サーバーが `warp:true` と正しい移動先を返すか確認）で行った。

## ワープのロード画面

- ブラックアウトではなく、ゲームのロード画面のような見た目に変更（`#warp-fade`）。暗い青の背景、ロードバー、"Now Loading..."、ヒント1行。0.3秒でフェードインしてからバーが約1.1秒で満ち、そのあとで瞬間移動して画面を戻す。
- **待っている間は自分の操作と移動送信を止める(`WorldScene.warping`)。** サーバーは warp を受け取った時点でもう移動先へ動かしているので、クライアントが旧位置から動き続けると速度検証で棄却され、補正が飛んで画面が割れる。ロード画面中の通常の補正は無視する。

## 物の回転（「物を置く」）

- 置く前の向きは `EditorScene.placeAngle`（度・時計回り）。Q で右90°、Shift+Q で左90°（パネルのボタン・数値欄でも可）。ゴーストにも反映され、置くと `ObjectDef.angle` に入る（0 のときは省略）。選択中は同じキーで置いた物を回せ、インスペクタに角度欄あり。
- 既存の `angle`（取り込み済みの物・`spawnObject` の `setAngle`）と同じ規約なので、プレイ側の改造は不要。
- **当たり判定の四角(`hit/hx/by`)は回転しない。** 絵の向きだけが変わる。影（別の物）も回さない。横倒しの木などで判定が合わなければ、幅/高さを手で入れ替える。

## NPCとの会話

- NPC＝セリフを持つ配置物。`ObjectDef.npc = { name?, lines[] }`（`lines` の1要素が1ページ）。専用のNPC種別は作らず、どの物（モブ・人間・樽でも）にも付けられる。サーバーは関与しない（会話は各自の画面だけ。マップ配布物に入る）。
- プレイ: 足元(`o.x, o.by`)から40px以内に入ると「💬 ○○と話す (E)」ボタン。E / Space / ボタンで開始・次ページ、Esc または64px以上離れると閉じる。会話中は自分の移動入力を止める（サーバーへは通常どおり位置を送るだけ）。文字は1文字ずつ表示、途中で押すと全文表示。ワープ・シーン停止でも閉じる。
- E/Space/Esc は `InputState.onAction/onEscape` 経由。ハンドラは `WorldScene.connect()` で張り、SHUTDOWN で外す（window リスナーはシーンより長生きする教訓の再適用）。チャット入力中は無効。
- 頭上の 💬(名前) タグはHUDタグ(`npc:<index>`)で、プレイ開始時に1回作る。物の追加・削除がないプレイ中だけの前提。
- エディタ: 物を選ぶとインスペクタに「セリフ(1行=1ページ)」と「名前」。セリフを空にすると解除。セリフ付きの物の頭上に水色の丸印。複製・範囲コピー/パーツ化でも `npc` は引き継ぐ。

## スタンプラリー（キーアイテム）

- データは `map.keyItems = [{ id, x, y, name? }]`（x,y はマス中央のpx）。`id` は位置を動かしても変わらない不変ID（取得済みの記録に使う）。島ごとに1個置く運用だが、数や島との対応はコードで縛らない（マップ側の約束）。
- **取得の記録は端末の localStorage(`sunnyside.stamps.v1`)だけ。サーバーには送らない。** 文化祭の「スタンプカード」用途なので不正対策より手軽さを優先した（コンソールからは書き換え可能）。ブラウザを変える/履歴を消すと最初から。カードの「はじめから」で消去(ページ再読込)。マップから消えたIDは数えない(`stamps.count`)。
- プレイ: 足元が星の中心から18px以内に来ると自動で取得（ボタン操作なし）。星は上下にゆれ、取ると跳ねて消える。取得済みの星は次回から表示しない。左上に「★ n/N」ボタン→スタンプカード(枠はマップのキーアイテム数ぶん)。取得時は上に通知、全部そろうとコンプリート表示。Esc でカードを閉じる。
- 星の絵は `game/starIcon.ts` のドット絵1つを、Phaserのテクスチャとカード用の画像(data URL)の両方に使う（素材ファイル不要）。
- エディタ「キーアイテム」ツール(K): クリックでマス中央に置く／星をドラッグで移動／右クリックで削除（全部Undo可）。「島ごとに自動配置」はラベルに「島」を含むグループのうちキーアイテムが無い島の中央に一番近い「歩ける」マスへ置く。島を動かすと、その上の星も一緒に動く（動かす前の範囲で判定）。島を削除しても星は残る。ツール中は星のあるマスを黄枠、星の無い島を赤枠で表示。
- 通知・カードは DOM。ボタンは `.touch` では左上の2段目に下げる。

## タイルセットにだけある果物・置物を「物を置く」で置く

- 経緯: 一度「パーツを1つの物に／タイル範囲をドラッグで物に」という作りで実装したが、**ユーザーの困りごとはそれではなかった**（取り消した: 9472da1）。本当の問題は、タイルセット画像には描かれている果物・野菜・家具・鉱石・木などが、「物を置く」の一覧(=GameMaker由来のスプライト)に無くて選べないこと。
- 作り: タイルセット画像を起動時(エディタ)に走査し、透明でない画素のつながり(8近傍)を1個の絵として自動で見つける（`editor/tileItems.ts`。枠が重なるものは1つにまとめ、80px超=地形・建物の部品と、6画素未満=ごみは除く。約170ms）。main で約200個（小〜16px:170 / 中〜32px:27 / 大:4）、forest で7個。「物を置く」の最後のタブ「タイルの絵」に、タイルセット切り替え・大きさ絞り込みつきで並べる。選ぶと普通の物と同じに置ける（回転・反転・複製・Delete・当たり判定・セリフ・Undo）。
- データ: `MapSpriteDef.crop = { tileset, x, y, w, h }`（`file` なし）。名前は `crop:<tileset>:<x>,<y>,<w>x<h>`。`game/cropSprites.ts` がタイルセット画像から1枚のcanvasテクスチャ(`obj/<名前>`、frame 0)を作る（ゲームは PreloadScene.create、エディタは選んだ時点）。原点は足元中央。素材ファイルは増やさない。
- 保存: 選んだだけで置いていない定義(`catalog:true && crop`)は map.json に書かない(`EditorScene.serialize`)。ゲームは配置されている物の定義だけ組み立てる（保存→再読込→プレイ画面で確認済み）。
- 「床に敷く（常にキャラより下）」を置くときに指定可（敷物・カーペット用）。
- 限界: 自動検出なので、1つの物が複数の塊に分かれて描かれている場合は別々の絵になる／近接して重なる別の物は1つにまとまることがある。80px超の大きな絵（建物の屋根、巨大な木のかたまりなど）は一覧に出ない。

- 注意: 自分のキャラ(`me`)は接続直後に届いていないことがあるので、降下先は `me` があればその位置、なければスポーン地点。`onPlayerAdd` の追従開始は演出中は保留し、演出の終わりで始める。開発用ブラウザペインはフレームが間引かれるため演出が極端に遅く見えるが、実ブラウザでは約4.7秒。

## 出店の共通の作り方と、7つの出店

- お好み焼き屋の作り方を一般化して、**1出店＝2ファイル**にした（`scripts/stalls/README.md` が決まりごとの全部）: `scripts/stalls/<id>.ps1`（専用ドット絵。出力は `client/public/brand/stall/<id>_*.png`）と `scripts/stalls/<id>.mjs`（`meta` と `layout(k)`）。
  - 道具: `scripts/lib/pixel.ps1`（描画。日本語は MS Gothic を1bit化）、`scripts/lib/stall-kit.mjs`（配置: `put/person/custom/cropAt/cropRect`。座標は草地の中心からのずれ dx と、上端からの足元 foot）、`scripts/preview-stall.mjs`（map.json に書かずに1枚絵で確認。出力は `reference/stall-previews/`＝git管理外）、`scripts/stall-assets.mjs`（素材の一覧・拡大）、`scripts/build-stalls.mjs`（島に組み立て。`--only` `--replace` `--dry`。書く前に自動バックアップ）。
  - アニメは「フレームを横一列に並べたPNG」＋`k.custom(name, ox, oy, {frames, fps})`。ゲーム側は既存の仕組み（`frames>1` のスプライトシートを自動でループ再生）のままで、コード変更なし。
- 出店と島: お好み焼き=浮島27、たい焼き=26、カフェ=25、チョコバナナ=20、たこ焼き=19、射的=24、コンサート会場=30（いずれも作る前は空だった島）。
- **作り方**: 共通の道具と見本（お好み焼き）を先に整え、出店ごとに別の担当（サブエージェント6つ）が並行して、自分のファイルだけを触って作った（`map.json` や共有ファイルには触らない決まり。確認は preview だけ）。最後に私が `build-stalls.mjs` で一括して組み立て、エディタで全部目視した（アニメ41個が再生されることも確認）。参考にした資料は各担当の報告に基づく。ゲーム画面の細かいピクセルアートの作例は検索で取れないことが多く、構成（何を置くと何の店に見えるか）の整理が中心。
- 人物スプライトの落とし穴（担当から）: `human_*_waiting` は釣り竿の線が、`*_carry` は箱を頭に載せた絵が入っているので、客や給仕には `idle` を使う。人物の体は約16px。
- PowerShell の落とし穴（担当から）: `[math]::Max(0, 小数)` は整数に丸められるので `0.0` と書く／ハッシュテーブルのキーは大文字小文字を区別しない（`Ascii` のパレットで `r` と `R` は両立しない）／`Clear` は `clear`(Clear-Host)に負けることがあるので透明は `Px $b x y 透明色` で。
- 限界: 話しかける会話は各出店の店主・客のNPCだけ（団体の実際の情報＝値段・時間・場所は未入力。事実が分からないので書かなかった）。ワープが無いので、スポーン島の外の出店へ歩いて行く手段は別途必要。`put` の `angle` は preview に反映されない（ゲームには反映される）。

## 画面サイズ

- **Phaser の Scale は `NONE`、幅・高さは `Math.floor(innerWidth/innerHeight)` を渡し、`window.resize` で `scale.resize()`。** RESIZE モードは親要素のサイズをそのまま使うため、ブラウザズームや Windows の 125% 表示（例: 1366×768 → 1092.8×614.4 CSS px）で小数サイズになり、WebGL のフレームバッファ作成が `Incomplete Attachment` で失敗した事例があった（開発中のエミュレーション環境で `450.4` を確認）。
- 開発中に「読み込みが途中で止まる」現象があったが、原因は **ブラウザペインが非フォーカスの間 requestAnimationFrame が絞られていた**こと。Phaser のローダーはゲームループで進むため、バックグラウンドのタブでは読み込みが進まない（通常の Phaser の仕様）。
